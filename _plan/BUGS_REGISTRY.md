## 2. Блок A — Мир, стриминг, активная область (`W-`)

### W-01 · P1 · Деревья и кусты стоят на воде — **ЗАКРЫТ (2026-11-05)**: согласованы маски со стороны воды: `shore_inset = 0.12` в `terrain_blend.gdshader` (полоса гашения воды у клетки суши, вода только убирается); общий шейдер для острова и мира
**Симптом:** S-W1s. **Источник:** `W_world_streaming.md` §2/W1.
**Механизм:** это **не** дефект генерации. Декор запрещён на воде явно (`WorldGenV2.cs:455`, `:489-519`). Виновата подпиксельная ватерлиния шейдера: в `terrain_blend.gdshader:74-111` при `f=0.5` (центр клетки) и `t = 0.5 − fbm + teeth` (`shore_curvature=0.45`, `teeth ∈ [−0.06, 0.12]`) вода залезает на клетку суши на **24…70 %**. Спрайт дерева непрозрачен в строках 2..60 из 64 (`tree.png`, 2840/4096 непрозрачных пикселей) ⇒ у берега больше половины деревьев «по колено» в воде. В стриминге хуже: тайл дерева собирается `Image.CreateEmpty` + `BlendRect` (`StreamingWorldView.cs:1519, 1534-1563`) — прозрачный фон поверх шейдера.
**Что делать:** после W-04 (общая таблица «Terrain/Biome → пиксели») согласовать маску воды и маску декора: либо декоративный сдвиг центра спрайта от ватерлинии, либо запрет декора в полосе `|t| < 0.12` у воды.
**Проверка:** скриншот берега на zoom 1.0 внутри и сразу за 1024.

### W-02 · **P0** · Шов/«недополоса» на границе 1024 — **ЗАКРЫТ (2026-11-05)**: второй рендерер земли выведен: землю и воду во всём мире рисует один `terrain_blend.gdshader` (`StreamingWorldView` кладёт только прозрачный декор), `streaming_ground.gdshader` помечен выведенным и не подключается. Шов 1024 больше не «смена рендерера», остаточное отличие — только данные генератора
**Симптом:** S-W2s. **Источник:** `W_world_streaming.md` §2/W2.
**Механизм:** ровно на линии 1024 переключаются **два независимых рендерера земли**: `MapRenderer._groundSurface` (ColorRect на 512 тайлов, `z = −2`, шейдер `terrain_blend`) и `StreamingWorldView._groundLayer` (плитки, `z = −1`, шейдер `streaming_ground`). Стриминг остров не рисует (`StreamingWorldView.cs:1873-1874`, `:978-982`). **Данные при этом непрерывны** — это доказано тестами генераторов (`TestWorldGenV2` тесты 2/3/5/6) ⇒ шов **чисто визуальный**: при береге/реке на кромке ватерлиния скачет на 0…±0.5 тайла. Вторая ветка гипотезы — транзиентная непокраска (бюджет 4 мс/кадр в `StreamingWorldView._Process`).
**Что делать:** сначала наблюдаемость (FEAT-W05: оверлей «кто рисует клетку» + счётчик непокрашенных), затем единый контракт «кто рисует землю» (FEAT-W02).
**Проверка `[рантайм]`:** 2–3 скриншота полосы на 1024 с интервалом ~0.5 с — отличает постоянный шов от непокраски.

### W-03 · P1 · Сглаживание воды потеряно в стриминге — **ЗАКРЫТ (2026-11-05)**: проверено: стриминг не рисует землю/воду вовсе (только прозрачный декор), кромка идёт через тот же `terrain_blend`; старый `streaming_ground.gdshader` помечен выведенным и не подключается
**Симптом:** S-W3s. **Источник:** `W_world_streaming.md` §2/W3.
**Механизм:** в `streaming_ground.gdshader` (63 строки) физически **нет** ни `terrain_map`, ни `evaluate_biome`, ни FBM/`shore_curvature`, ни тени берега. Вода детектируется по цвету пикселя (`:27`) ⇒ за 1024 ступени 64 px — видимые «лесенки».
**Что делать:** шаг 5 волны 4 — общая таблица «Terrain/Biome → пиксели/плитка» + перенос береговой функции в стриминговый шейдер.
**Проверка:** скриншот одного берега на zoom 1.0 по обе стороны 1024.

### W-04 · P1 · Зона внутри и снаружи 1024 выглядит по-разному — **ЗАКРЫТ (2026-11-05)**: мировые зоны при подтверждении ставятся как ГОТОВЫЕ (`Stockpile`/`Crop`), плановая метка снимается — визуальный контракт «зона внутри и снаружи 1024» один. Плюс единая точка `PaintZoneCell` в `ZoneDraftTool`
**Симптом:** S-W4s. **Источник:** `W_world_streaming.md` §2/W4.
**Механизм:** 4 канала различия. Ключевой: тайл зоны на острове — `_stockpileLayer` + `SourceGrass` + `modulate` **без рамки** (`MapRenderer.cs:326, 397-400`), а в стриминге — bordered-тайл (`StreamingWorldView.cs:1379-1400`). Следствие: **подтверждённая зона снаружи выглядит как ghost зоны внутри** (`:1654-1673`).
**Что делать:** шаг 6 волны 4 — общий слой маркеров зон + один предикат `CanPlaceZone`.
**Риск:** `ZoneDraftTool` — 822 строки, в цикле ui.

### W-05 · **P0** · Авто-стены вокруг зоны не ставятся за 1024 — **ЗАКРЫТ (2026-11-05)**: единый предикат кольца `IsRingWallable`: остров → `ConstructionManager.CanPlaceWall`, мир → `WorldPlacement.CanPlaceWall`; превью кольца через кромку включено, `WorldPlacementPass.MaxScannedCells` соблюдён. Остаток («чертёж поставился и пропал» до загрузки чанка) — это исполнитель мира, учтён в L-04
**Симптом:** S-W5s и S6. **Источник:** `W_world_streaming.md` §2/W5 + собственная проверка Лида.
**Механизм (полная цепочка, проверено):**
1. `ZoneDraftTool.RecalcWalls()` строит кольцо стен вокруг клеток зоны (`ZoneDraftTool.cs:336-401`). Для мировых клеток — `_worldWallCells.Add(p)` только если `WorldPlacement.CanPlaceWall(x, y)` (`:369-371`).
2. `StreamingToolPlacement.IsWorldBlueprintBlocked` = `!WorldPlacementPass.WorldBlueprintsSupported && !IsIslandCell(...)` (`StreamingToolPlacement.cs:67-68`).
3. `WorldPlacementPass.WorldBlueprintsSupported = false` — **константа** (`WorldPlacementPass.cs:37`).
⇒ для любой клетки вне `[0,1024)²` `CanPlaceWall` = false ⇒ кольцо пусто.
**Почему нельзя «просто поставить true»:** у мировых планов нет исполнителя (`WorldJobBoard` не подключён, §118 фаза 5 снесла мир-агентов), а запись требует резидентного чанка (`StreamingWorldView.cs:282-283`). Включение флага вернёт баг «чертёж поставился и пропал».
**Что делать:** только вместе с волной 4 (исполнитель мира). До этого — честный UI-запрет вместо лога в консоль (см. J-06).

### W-06 · P1 · Тесты шва закреплены на устаревшей границе 512 — **ЗАКРЫТ (2026-11-05)**: island-seam тесты переведены на `WorldModel.IslandTiles` (1024): `test_streamingview_decor_seam.cs`, `TestDestroyerWorldGen.cs` (WTEST 5), `TestAdversarialConstruction.cs`. Тесты 512-тайловых РЕГИОНОВ генератора не тронуты осознанно
**Источник:** `W_world_streaming.md` §2/W6.
**Механизм:** `test_streamingview_decor_seam.cs:112`, `TestDestroyerWorldGen.cs:211-275`, `TestDestroyerStreaming.cs:222-234`, `TestWorldGenSeamAudit.cs:170,177`, `TestAdversarialConstruction.cs:212-220` проверяют шов на 512. При этом `GenerateColonyWindow`, под который они написаны, в продукте уже не участвует (заменён `ActiveArea.Fill`). **Автоматического теста шва на 1024 нет вообще** — то есть W-02 нельзя поймать регрессом.
**Что делать:** FEAT-W03 (волна 0) — тест шва на 1024 + починка трёх тестов на 512.

### 9.1. Подблок G — Генерация мира, планетарная гидрология и спавн

#### G-01 · **P0** · Спавн в океане / на микро-пятачке среди воды после выбора суши на карте мира `[статически]`
- **Симптом:** S-G1. Игрок выбирает зелёный регион (равнину/лес) на карте мира, подтверждает выбор, но колония генерируется посреди открытого моря, а пешки спавнятся на искусственном пятачке 14 тайлов посреди воды.
- **Файлы:**
  - `src/ui/streaming/WorldMapOverlay.cs:350-377`
  - `scenes/main/Main.cs:465-467, 496`
  - `src/core/world/activearea/ActiveArea.cs:175-199`
  - `src/core/world/generation/WorldGenV2.cs:489-535, 550-605`
  - `src/core/world/generation/UnifiedWorldGenerator.cs:489-535, 550-605`
- **Механизм:**
  1. На карте мира клик выбирает `RegionKey(cellX, cellY)`. Проверка `t >= 6 && t <= 8` в `WorldMapOverlay.cs:365` блокирует только `DeepWater`. Мелководье, прибрежная полоса и водоёмы других типов клик не блокируют. Если клик произошёл до готовности полной детализации (пока `_isTileDataPreview == true`), проверка идёт по превью 512×256 со смещением до 4 регионов.
  2. Но главное: 1 регион = 512×512 клеток мира. `Main.cs:496` ставит `SetWorldOrigin(region.X * 512, region.Y * 512)`. Колония создаётся размером 1024×1024 (2×2 региона). Камера и стартовое зерно спавнятся в локальном центре `(512, 512)`.
  3. Внутри региона локальный генератор `WorldGenV2.SampleCellCore` накладывает шум холмов, синусоидальные меандры рек, озера и прибрежный варпинг (`coastalMod`: бухты, фьорды до 4000 единиц глубины). Центр региона или колонии легко попадает в залив, море или озеро.
  4. В `ActiveArea.cs:175-199` `ApplyStartClearance` выжигает круг радиуса 14 клеток вокруг центра в `Grass`, даже если вокруг глубокая вода. В итоге игрок видит микро-пятачок 14 клеток суши посреди бескрайнего океана.
- **Что делать:** В `OnRegionSelected` перед запуском мира делать кольцевой скан окрестности с выбором гарантированно сухой стартовой точки (суша радиусом $\ge 64$ тайлов без рек и моря) либо смещать `WorldOrigin` к безопасному центру материка.

#### G-02 · **P0** · Полный рассинхрон гидрологии планеты и локального мира (исчезновение глобальных рек и оазисов) `[статически]`
- **Симптом:** S-G2. На карте мира игрок видит крупные континентальные речные артерии с притоками и оазисами в пустыне, кликает высадку у реки, но в игре реки нет вовсе, а вместо неё течет случайный ручей иной формы.
- **Файлы:**
  - `src/core/world/climate/PlanetaryHydrology.cs:199-245`
  - `src/core/world/generation/UnifiedWorldGenerator.cs:550-565`
  - `src/core/world/generation/WorldGenV2.cs:550-565`
- **Механизм:**
  1. `PlanetaryHydrology.SimulateGlobalHydrology` на карте мира симулирует физический гравитационный D8-сток, создаёт древовидные русла и заменяет тайлы на реку (`riverTile`), а прилежащую пустыню — на оазисы (равнины и рощи).
  2. Локальные генераторы (`WorldGenV2` и `UnifiedWorldGenerator`) результат `PlanetaryHydrology` **не читают вообще**. Реки генерируются локально через синусоидальный меандр `(rwx * 3 - rwy * 4) / 5 + meanderOffset` с периодом 512. Глобальные артерии и поймы полностью теряются в локальном мире.

#### G-03 · P1 · Несоответствие габаритов колонии и региона на глобальной карте (512 vs 1024) `[статически]`
- **Симптом:** Красная рамка колонии на карте мира выделяет область 512×512 (1 регион), тогда как колония занимает 1024×1024 (2×2 региона).
- **Файлы:** `src/ui/streaming/WorldMapOverlay.cs:448-458`, `scenes/main/Main.cs:20-27`.

#### N-01 · P1 · Сохранение островных дельт неатомарно и без fsync — потеря ВСЕЙ прогрессии колонии при сбое питания/крэше `[статически]`
- **Симптом:** игра закрылась аварийно / пропало питание в момент сохранения — файл `<zoneId>.island.delta` оказывается отсутствующим или мусорным; при следующем запуске «островные дельты не загружены», вся сессия (срубленные деревья, добытая руда, стены, грядки, содержимое складов, предметы на земле) потеряна.
- **Механизм (доказательство):** `src/core/world/mutation/IslandOverrideStore.cs:290-313`
  ```csharp
  string temp = path + TempSuffix;
  using (var stream = new FileStream(temp, FileMode.Create, FileAccess.Write, FileShare.None))
  using (var writer = new BinaryWriter(stream)) { … }   // fsync НЕ вызывается
  if (File.Exists(path))
      File.Delete(path);      // ← окно: целевого файла нет
  File.Move(temp, path);      // ← до этого места крэш = потеря и старого, и нового
  ```
  Контраст — правильный образец в том же слое: `src/core/world/streaming/storage/WorldChunkStore.cs:88-99` — `stream.Flush(flushToDisk: true);` + `File.Move(tempPath, targetPath, overwrite: true);` (комментарий там же объясняет, зачем это сделано: bughunt 05-4, «валидное имя + мусор» после сбоя питания).
  ⇒ чанк-стор выживает при сбое, а **островной стор — нет**, хотя именно в нём лежит вся не-воксельная прогрессия острова (§118 фаза 4).
- **Условие срабатывания:** сохранение вызывается только на выходе/смене колонии (`scenes/main/Main.cs:846`, `:141`); сбой питания/`kill -9` в пределах записи файла (до десятков МБ) ⇒ потеря.
- **Что делать:** заменить `Delete`+`Move` на `File.Move(temp, path, overwrite: true)` (или `File.Replace`), добавить `stream.Flush(flushToDisk: true)` перед закрытием, а `.tmp` при загрузке — подхватывать, если целевого нет.
