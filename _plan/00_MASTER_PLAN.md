## 2. Как назначать модель и уровень мышления агентам (механика)

### 2.1. Пять механизмов делегирования и что каждый умеет

Это ключевая таблица: **половина очевидных способов не даёт того, что кажется**.

| Механизм | Задать модель на агента | Задать effort на агента | Вердикт |
|---|---|---|---|
| **`spawn_teammate`** (Agent Teams, «тиммейты») | ❌ **нет и не будет** — конфиг тула содержит только `freshProvider`/`forkProvider`; ребёнок наследует `agent-default-model` | ❌ нет | Годится для **долгих именованных** ролей. Модель у всех одна. |
| **`subagent` / `subagent_fork`** (как сейчас) | ❌ поля `provider`/`model`/`reasoning_effort` **не выставлены в схеме**, потому что `modelSelectionSettings` = `false` | ❌ | То же ограничение. |
| **`subagent` с `modelSelectionSettings: true` + Host-политика** | ✅ `provider` + `model` на каждый вызов | ✅ `reasoning_effort` | **Целевой способ.** Требует одной правки патча + одной галочки (см. 2.2). |
| **`subagent` с `agentOptions`** | ✅ но **фиксированная** для всех детей | ✅ | Если нужна одна модель на всю волну. |
| **`workflow` → `agent(prompt, {provider, model})`** | ✅ на каждого агента | ❌ (только route-дефолт) | **Работает уже сейчас, без правок.** Лучший способ для веера задач (audit по 20 файлам, миграция и т.п.). |
| **Смена `agent-default-model` между волнами** | ✅ но **фазово**, а не на агента | ✅ | Костыль, но рабочий: выставить модель → спавнить волну → вернуть. |

### 2.2. Рецепт: включить полный per-agent контроль (3 шага, без перезапуска)

**Шаг 1 — разрешить тулзе принимать маршрут.** В `C:\Users\PC\.dsh\profiles\desktop\cordis.patch.yml` добавить запись (id обязан совпасть с базовым — `tool-subagent`):

```yaml
- id: tool-subagent
  name: "@deepseek-ai/dsh-tool-subagent"
  config:
    provider: spawn
    toolName: subagent
    modelSelectionSettings: true   # ← включает поля provider/model/reasoning_effort
```

Опционально — фиксированный дефолт для всех детей (вместо Host-политики):

```yaml
    agentOptions:
      provider: apireformboss
      model: deepseek-v4.1-flash-1017
      reasoningEffort: high
      maxTokens: 32768
```

**Шаг 2 — выдать политику в GUI.** Сайдбар → **Plugins** → группа **Official** → **Subagent** → секция **Model selection**: включить переключатель и отметить точные маршруты (провайдер + модель) из §1.2 → **Save**. Одна кнопка пишет обе секции (`subagent` и `subagent-model-selection`).

**Шаг 3 — проверить.** После включения в схеме `subagent` появятся `provider`, `model`, `reasoning_effort`, а также отдельный тул `list_subagent_models` — по нему видно, какие маршруты реально разрешены.

**Ограничения, которые надо знать заранее:**
- Политика **фиксируется в сессии при её создании** и наследуется детьми; правки настроек не меняют уже созданную сессию. ⇒ после изменения — **новая сессия**.
- Требуется бэкенд, поддерживающий `agentOptions`. ACP / Codex / Claude Code — **отвергают**, а не игнорируют. Наш `spawn` — in-process, подходит.
- `subagent_fork` намеренно **не** получает model selection: форк должен оставаться побайтово той же модели, чтобы история попадала в KV-кэш.
- `Model selection` **нельзя** применить к уже запущенному тиммейту — только при спавне.

### 2.4. Подводные камни

1. **`reasoningEffort: off` — не «быстрее», а «без рассуждения».** Для задач вида «найди корень бага в 39-файловом SCC» это гарантированный провал. Ставьте `off` только на чисто механические правки.

3. **`gpt-5.6-luna`, `claude-haiku-5-5` не объявляют `reasoningEfforts`** ⇒ уровнем управлять нельзя, уйдёт дефолт провайдера. Не планируйте их в матрицу.
4. **`qqq` (localhost:8797)** может быть не поднят — `deepseek-v4-pro`/`gpt-6-astra` недоступны без локального шлюза.
5. **Экономия на `max` ложная.** В этой сессии четыре отчёта по 500–900 строк уложились в один прогон; провал из-за `low` стоил бы дороже.
6. **Effort не влияет на размер контекста.** Для `PLAN.md` (806 КБ) нужна модель с длинным контекстом, а не высокий effort.

## 8. Приёмка (Definition of Done)

Задача закрыта, когда **все четыре** пункта выполнены:

1. `dotnet build Game.csproj` → **0 ошибок, 0 предупреждений** из изменённых файлов.
2. Есть **зелёный автоматический тест**, который падал бы без правки. Для правок без тестов (документация) — `viz_cli coverage/plandrift` не ухудшился.
3. **Замер до/после** по тому же счётчику, что указан в приёмке задачи (не «стало лучше», а число).
4. Запись в реестр обновлена: дефект → `закрыт` с указанием коммита/теста; новая находка → новая строка.
