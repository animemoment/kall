### U2-01 · **P0** · Клики сквозь окно «Зоны»: явный `Dim.MouseFilter = Stop` затирается рекурсией

- **Файлы:** `src/ui/controllers/HUDController.cs:171` (`SetupIndustryButtons()`), `:183` (`SetMouseFilterRecursive(this)`), `:1189-1196` (`Dim` → `Stop`), `:2125-2153` (рекурсия), `scenes/ui/hud.tscn:467` (`Dim` = `ColorRect`).
- **Механизм (доказан порядок):** в `_Ready` сначала `SetupIndustryButtons()` ставит `Dim.MouseFilter = Stop` и вешает `GuiInput`-закрытие (`:1189-1196`), затем `:183` вызывает `SetMouseFilterRecursive(this)`, где `Stop` получают только `BaseButton` (`:2135-2137`) и `Panel/PanelContainer` (`:2139-2141`), **всё остальное → `Ignore`** (`:2143-2146`). `ColorRect` попадает в `Ignore` ⇒ подложка не ловит клик, `GuiInput`-ветка мёртвая, ЛКМ уходит в `PlayerInteractionManager._UnhandledInput` (`PlayerInteractionManager.cs:87`) и работает по миру.
- **Минимальная правка — 3 варианта:**

  **A (рекомендуемый, локальный): пост-проход сразу после рекурсии.** Не менять порядок `_Ready`, а после `:183` вернуть `Stop` тем подложкам, которым он нужен:
  ```csharp
  // HUDController.cs — после строки 183 (SetMouseFilterRecursive(this);) добавить:
  ApplyModalBackdropFilters();

  // и новый метод рядом с SetMouseFilterRecursive (после :2153):
  private void ApplyModalBackdropFilters()
  {
      // Подложка окна «Зоны» обязана ловить клик: рекурсия (:2143-2146)
      // сбрасывает ColorRect в Ignore и убивает GuiInput-обработчик из :1189-1196.
      if (_zoneContainer?.FindChild("Dim", true, false) is Control dim)
          dim.MouseFilter = MouseFilterEnum.Stop;
  }
  // было: Dim остаётся Ignore (после :183)
  // стало: Dim = Stop, GuiInput из :1189-1196 снова работает
  ```
  Плюсы: 0 риска для остальных узлов, лечит и порядок, и будущие окна (одна точка). Минусы: про подложку надо помнить при добавлении нового окна.

  **B (системный): рекурсия ДО `Setup*`.** Перенести `SetMouseFilterRecursive(this)` из `:183` в начало `_Ready` (например, сразу после блока `FindChild`, до `SetupMapModeControls()` на `:141`), тогда все явные `Stop` из `Setup*` (включая `Dim` в `:1191` и кнопки `:187-254`) останутся в силе — ровно та же схема «сначала общий фильтр, потом явные исключения», что уже принята для кнопок `:185-254`. Плюсы: чинит весь класс. Минусы: `Control.MouseFilter` по умолчанию = `Stop`, поэтому **каждый** Control, созданный в `Setup*` без явного фильтра, начнёт перехватывать мышь (сейчас таких три: `IndustryGrid`-ячейки `VBoxContainer` `:1238`, `Res_*` `HBoxContainer` `:1543`, возможные будущие) — нужен прогон по всем окнам.

  **C (одна строка, как страховка к A): `ColorRect` в список `Stop`.**
  ```csharp

  // стало
  else if (control is Panel or PanelContainer or ColorRect) control.MouseFilter = MouseFilterEnum.Stop;
  ```
  В `hud.tscn` `ColorRect` ровно один (`Dim`, `:467`), поэтому риск минимален — но при появлении полноэкранного `ColorRect`-затемнения он начнёт блокировать ВЕСЬ ввод.
- **Что НЕ трогаем:** не переписываем рекурсию целиком и не вводим «слой модальности»; не трогаем `Panel`/`PanelContainer`-ветку; окна `Farm.tscn`/`Build.tscn`/`JobDisplay.tscn` — у них свои `ConfigureInputBlocking`/`_Ready` (исследованы отдельно, этой правкой не задеваются).
- **Риск:** A/C — почти нулевой (меняется фильтр ровно одного узла `Dim`); B — средний (см. минусы). Откат — убрать 2–3 строки.

#### U2-01-b · та же болезнь у других подложек/панелей (проверено)
